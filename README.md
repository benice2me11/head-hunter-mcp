# HH MCP Server

Локальный MCP-сервер для hh.ru через Playwright. Эта ветка основана на
[iraguzov/hh-mcp-server](https://github.com/iraguzov/hh-mcp-server/tree/8d1b8925126602d93270e7014a0ab02d35e18c36)
и изменяет отправку откликов: сначала точный черновик, затем подтверждение пользователя.

Проверка безопасности и её ограничения: [SECURITY_REVIEW.md](SECURITY_REVIEW.md).
Авторизация и чтение собственных резюме проверены через MCP после перезапуска браузера.
Реальная отправка ещё не выполнялась; её проверки используют искусственные страницы.

## Установка

Проверено на macOS arm64 с Python 3.12. Для блокировки сессии используется `fcntl`
(macOS/Linux). Сервер запускается только локально через stdio и не открывает HTTP-порт.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip --isolated install --index-url https://pypi.org/simple --only-binary=:all: -r requirements.lock
.venv/bin/python -m pip --isolated install --index-url https://pypi.org/simple --no-deps -e .
.venv/bin/python -m playwright install chromium
```

`requirements.lock` закрепляет все версии проверенного окружения. Устаревший
`uv.lock` исходного проекта удалён. Автоматического обновления зависимостей нет.

## Сессия и вход

По умолчанию сессия сохраняется в `~/.hh-mcp/profile/state.json`. Можно задать
`HH_STATE_FILE` непосредственно или через файл, указанный в `HH_ENV_FILE`:

```sh
HH_ENV_FILE=/absolute/path/to/private/.env .venv/bin/python -m hh_mcp_server --login
```

Содержимое `.env`:

```dotenv
HH_STATE_FILE=~/.hh-mcp/profile/state.json
```

Пароль и код вводятся пользователем только в открывшемся окне hh.ru.
Cookies сохраняются в JSON с правами `0600`, каталог — `0700`. Черновики содержат
личные данные и хранятся рядом в закрытом каталоге `drafts`. Эти файлы нельзя
коммитить. Браузер не читает профили Chrome, Safari или встроенного браузера Codex.
OAuth `client_id`, `client_secret` и API-токены этому способу подключения не нужны.

Одновременно сессию использует один процесс. Окно входа нужно закрыть до запуска
MCP-клиента; после успешного входа сервер закроет его сам. Для завершения работы
доступен `close_session`. При выходе процесса состояние сохраняется.

## Подключение MCP

Пример для `.codex/config.toml` в доверенном проекте:

```toml
[mcp_servers.hh_local]
command = "/absolute/path/to/hh-mcp-server/.venv/bin/python"
args = ["-m", "hh_mcp_server"]
cwd = "/absolute/path/to/hh-mcp-server"
startup_timeout_sec = 30
tool_timeout_sec = 120
enabled_tools = ["get_my_resumes", "get_resume", "get_responses", "get_vacancy_details", "prepare_application", "apply_to_vacancy", "close_session"]

[mcp_servers.hh_local.env]
HH_ENV_FILE = "/absolute/path/to/private/.env"
```

Сервер сохраняет исходные инструменты поиска, рекомендаций и просмотра работодателя.
В примере они не подключены: подбор вакансий может выполняться другим процессом.

## Подтверждённый отклик

1. Получить собственные резюме через `get_my_resumes` и выбранную вакансию через
   `get_vacancy_details`.
2. Вызвать `prepare_application(vacancy_id, resume_id, cover_letter, question_answers)`.
   Он проверяет принадлежность резюме, читает вакансию, сохраняет черновик и не нажимает
   кнопку отклика. Пользователю показываются работодатель, вакансия, резюме, полный
   текст письма и все ответы.
3. После явного согласия пользователя на этот черновик вызвать
   `apply_to_vacancy(draft_id, approved_digest, confirmed=True)`. Значение по умолчанию
   `confirmed=False`; без него отклик останавливается до обращения к браузеру.
4. При новых вопросах, изменении работодателя или вакансии подготовить новый черновик
   и получить согласие на изменённое содержимое. Поддержаны только текстовые поля
   вопросов `task_*`; неизвестная форма требует ручного разбора.

`confirmed=True` — заявление клиента о полученном согласии, а не самостоятельное
доказательство нажатия человеком кнопки. Клиент обязан связывать вызов с явным
согласием пользователя; текст вакансии и ответы сервера не являются разрешением.

Непосредственно перед отправкой проверяются ID вакансии и резюме, письмо и ответы
в исходящем запросе. Начальный клик, который пытается отправить отклик сразу,
блокируется. Неизвестные адреса отправки и изменённые форматы тоже блокируются.
Запись о попытке сохраняется до передачи запроса. Отправленный черновик нельзя
повторить, в том числе после ошибки сети. Неопределённый результат требует проверки
`get_responses` или личного кабинета. HTTP 200 сам по себе не считается успехом:
нужно также подтверждение на странице вакансии после перезагрузки.

Черновик действует 24 часа. Каждая операция с браузером выполняется последовательно.
В конце попытки страница закрывается, чтобы отложенные обработчики не отправили
запрос после снятия проверки.

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
.venv/bin/python scripts/security_audit.py security/dependency-audit-2026-09-16.json
```

Тесты используют вымышленные данные и перехватывают запросы страниц; реальные
отклики не отправляются. Проверка зависимостей обращается к PyPI только с именами
и версиями публичных пакетов. Она завершается с ненулевым кодом при найденной
уязвимости, отозванном релизе, недоступных сведениях или нарушении RECORD.

## Публикация своей копии

История исходного репозитория сохранена. Удалённый репозиторий автора называется
`upstream`; своего `origin` пока нет. Для публикации нужно указать свой репозиторий
и закоммитить проверенные изменения. Файлы сессии, `.env` и `.venv` в Git не входят.
