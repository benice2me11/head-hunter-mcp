# Проверка безопасности — 16 сентября 2026

## Дополнение R2

После исходной проверки ниже добавлены приватный журнал с flock/fsync, ссылки на
согласие и сверку истории, отмена, защита возможности между разными черновиками и
aliases, содержательные снимки резюме/условий и запрет POST при подготовке.
Локальная база — `1b2bf97` плюс незакоммиченные изменения; прежняя правка README
сохранена. Итог — **46/46 тестов**, отчёт
`security/test-results-r2-2026-09-16.txt`; `pip check` успешен. Новый stdio-процесс
прочитал два полных собственных резюме и условия существующей карточки, затем
закрыл сессию. Частные тексты и доказательства остаются вне этого репозитория.

Все проверки отправки используют вымышленные данные и полностью перехваченные
страницы. Реальные черновики и отклики не создавались. Действительность согласия
проверяет клиент: ссылка в журнале не является криптографическим удостоверением
авторства сообщения. Полнота реальной истории hh, обмен с мониторингом и
восстановление после потери данных отдельно ещё не приняты. Неизвестные структуры
страниц блокируют отправку. Зависимости не менялись, новый аудит уязвимостей не
заявлен; нижеследующий первоначальный аудит сохраняет собственную дату и границы.

## Вывод и границы

В просмотренном исходном коде сервера не обнаружены сбор чужих локальных данных,
передача cookies автору, выполнение произвольных команд или обфусцированный код.
Это ограниченная проверка исходников, зависимостей и поведения на искусственных
страницах, а не гарантия отсутствия вредоносного кода во всей цепочке поставки.

Основа: [iraguzov/hh-mcp-server, commit 8d1b8925126602d93270e7014a0ab02d35e18c36](https://github.com/iraguzov/hh-mcp-server/tree/8d1b8925126602d93270e7014a0ab02d35e18c36).
Просмотрены модули сервера, CLI, браузера, авторизации, парсинга, MCP-инструментов,
метаданные сборки и локальные изменения. Новые версии upstream автоматически не
подтягиваются. Правки находятся в отдельной локальной ветке.

До просьбы о проверке уже были установлены зависимости и открыта страница входа
в отдельном Chromium. После просьбы процесс входа остановлен. После завершения
проверки пользователь вошёл в отдельный Chromium. Сессия сохранена; чтение
собственных резюме через новый процесс MCP подтверждено. Реальные отклики не отправлялись.

## Обнаруженные и исправленные проблемы

| Проблема | Изменение |
|---|---|
| Аргумент `resume_id` исходного инструмента фактически игнорировался | Выбор резюме в форме и проверка его ID в исходящем запросе |
| Отсутствие поля письма не останавливало отправку | Непустое согласованное письмо обязательно заполняется и проверяется |
| Отсутствие видимой ошибки принималось за успех | Проверяются отправленный запрос, HTTP-ответ и положительный маркер после перезагрузки |
| Вызов для «получения вопросов» мог сразу откликнуться | Подготовка черновика не нажимает Apply; ранние POST блокируются |
| Не было привязки отправки к проверенному содержимому | Черновик, SHA-256 содержимого, срок 24 часа, явный параметр подтверждения |
| После неопределённой отправки мог появиться дубль | Состояние записывается до передачи запроса; повтор этого черновика запрещён |
| Проверка входа полагалась на отсутствие URL логина | Проверяется доступ к странице собственных резюме и наличие маркера аккаунта |
| Сессия не имела явных ограничений доступа | Атомарные файлы `0600`, каталоги `0700`, блокировка совместного использования |
| Несколько операций могли управлять одной страницей | Последовательное выполнение MCP-вызовов и блокировка профиля между процессами |
| HTTP-транспорт создавал лишнюю сетевую поверхность | CLI допускает только локальный stdio |

В первоначально установленном окружении `mcp==1.26.0` PyPI сообщил
`GHSA-hvrp-rf83-w775`, `GHSA-jpw9-pfvf-9f58`, `GHSA-vj7q-gjh5-988w`.
Они относились к экспериментальным задачам, HTTP-сессиям и WebSocket-транспорту;
планируемый локальный stdio эти режимы не использует. SDK всё равно обновлён до
`1.28.1`. Также обновлён pip с `25.0.1` до `26.2`.

После первой смены версии FastMCP проверка выявила пересечение установленных
файлов FastMCP/FastMCP-slim. Окружение пересобрано с нуля. В рабочем окружении
закреплены `fastmcp==3.2.0`, `mcp==1.28.1`, `playwright==1.63.0`;
остальные версии перечислены в `requirements.lock`.

  Проверялись только чтение и закрытие сессии; личные данные не включены в этот отчёт.

[Документация PyPI JSON API](https://docs.pypi.org/api/json/) описывает сведения об
известных уязвимостях конкретного релиза. Отсутствие записей не означает отсутствие
неизвестных уязвимостей. RECORD проверяет согласованность установленного пакета с его
собственными метаданными, а не независимую подлинность или безопасность автора.
Зависимости и Chromium построчно не аудировались; версии закреплены, внешние Python
зависимости устанавливались из бинарных wheel с публичного PyPI.

## Данные и остаточные ограничения

- Пароль и одноразовый код вводятся только на hh.ru самим пользователем. Код не
  читает чужие браузерные профили или системное хранилище паролей. Сохранённая сессия
  всё равно даёт доступ к аккаунту и должна оставаться локальной.
- Сервер передаёт клиенту MCP запрошенные данные резюме, вакансий и откликов — это
  назначение интеграции. Во время работы Chromium сайт hh.ru может загружать свои
  сторонние ресурсы. При отправке действует ограничение HTTPS-доменами hh.ru и
  hhcdn.ru; полноценной изоляции всего процесса на уровне ОС нет.
- Параметр `confirmed` и digest не удостоверяют личность человека, который одобрил
  черновик. Явное согласие в интерфейсе остаётся обязанностью MCP-клиента.
- Реальные страницы и формат запроса hh могут отличаться от тестовых. Неизвестная
  форма останавливает отправку; обещать работоспособность реального отклика до
  отдельного согласованного испытания нельзя. CAPTCHA и дополнительные подтверждения
  автоматически не обходятся.
- Автоматического расписания, массовых откликов и повторных отправок не добавлено.
  Регулярный сбор вакансий в другом процессе не менялся.

## Дополнение: текущая форма и сериализация, 16 сентября 2026

Добавлены распознавание единственного видимого выбранного заголовка резюме и
ожидание асинхронного поля письма. Проверка исходящего ID сохраняется: совпавший
заголовок не разрешает передачу другого резюме. Для textarea допускается только
стандартное преобразование LF/CRLF при сериализации формы; остальные символы,
пробелы, пустые строки и ответы должны совпасть. Скрытый шаблон предупреждения
не считается требованием сменить приватность; видимое предупреждение останавливает
отправку до отдельного разрешения.

Полный прогон: 55 тестов, включая реальную браузерную multipart-сериализацию на
перехваченном синтетическом сайте и отрицательные проверки подмены. Лог:
`security/test-results-r3-form-encoding-2026-09-16.txt`. Выполнен один отдельно
согласованный живой отклик с положительным маркером после reload и независимой
проверкой истории. Две предшествовавшие остановки до POST сохранены в приватном
журнале клиента; фактическая передача одна. Подробности аккаунта и пакета в этот
репозиторий не перенесены. Публикация кода не выполнялась.
